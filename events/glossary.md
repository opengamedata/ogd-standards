## Glossary

* **Game Data** : A blanket term for all data that describes gameplay, whether the data came directly from the game or was derived later.
* **Open Game Data Pipeline** : This refers to the Open Game Data tools that collect telemetry from games, perform transformations on the data, and make datasets available online.
* **Event Data** : A type of data within the OGD pipeline. Event data describe individual occurrences within a game. Each Event is a single instance of a data structure encoding the occurrence of some interaction or change in game state at a specific point in time. 
* **Telemetry Data** : Event data that is directly generated by a game. This is the typical input to the OGD pipeline. Telemetry is distinct from post-hoc event data that may be added to augment a dataset. In other words, all telemetry data is event data, but not all event data is telemetry.
* **Event Parameter** : A single element of the Event data structure. The set of event parameters is constant across all events for all games in the system. Game-to-game and event-to-event differences are captured by parameter values, not by the data structure.
* **Data Format** : A description of the literal contents and structure of a data file. For example, a comma-separated values (CSV) format describes a file with commas separating each value. The OGD event file format describes a file with tab-separated values (TSV) that use a specific set of columns, derived from the OGD event schema.
* **Schema** : A description of the structure and semantics of a type of data. Format + semantics = schema. The OGD event schema, for example, describes what elements are to be included as part of any event. This includes both the literal naming and structure (which are used to derive appropriate formats for storing event data), as well as a semantic description of what each element represents or means.
* **Event Standard** : The “OGD Event Schema v1.0” introduces a numbering system to allow equivalent events across games to be represented as belonging to a common “type” of event. 
* **Logging Specification** : A game-specific standard that defines the set of events the game produces. Similar to the upcoming “OGD Event Standard,” a single-game logging specification includes a small schema for each event, including the name, a semantic description of what happens in the game to trigger the event, and a list of data elements with semantic descriptions. This is often informally called a “logging schema” or “game schema” or even (confusingly) “event schema.”
* **Logging Library** : A collection of software components that enable event data to be constructed and sent from a game to a data collection (logging) API.
* **Active player** : the player whose gameplay experience is captured by a particular event. This is distinguished from, for example, other players in a multiplayer game.
* **PROPOSED - Ego-/Exo-** : prefixes to distinguish between the active player (whose gameplay is captured by a particular event) and external players/characters. Ego-player would refer to the “active player, and exo-player would refer to other players in a multiplayer game. Exo-character would refer to any in-game character controlled by any means other than the active player (i.e. by a scripting, an AI agent, or an exo-player).
* **NPC** : An in-game character that is controlled by the game system. This may be an AI agent, or a character controlled through fixed behavior scripting. It does not include other players in a multiplayer game
* **AI agent** : An in-game character that is controlled by the game system in a manner approximately equivalent to a player - that is, the character is controlled dynamically rather than through fixed behavior scripting.
